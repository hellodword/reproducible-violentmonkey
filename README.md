# reproducible-violentmonkey

Independent byte-for-byte reproduction verifier and release metadata tracker for [Violentmonkey](https://github.com/violentmonkey/violentmonkey) packages published on Mozilla Add-ons (AMO).

Background discussions from upstream:

- https://github.com/violentmonkey/violentmonkey/issues/1109
- https://github.com/violentmonkey/violentmonkey/issues/587#issuecomment-515380084

> **tophf**: all you need is to build the source code and compare it to the released version, which is what AMO (addons.mozilla.org) reviewers do
> **gera2ld**: The AMO reviewers make sure that the code generated by them is exactly the same as that submitted by us, otherwise the add-on will be rejected.

## How Verification Works

For a given AMO version, `repro`:

1. Downloads the published AMO `.xpi`, verifies add-on identity and version, and strips standard Mozilla `META-INF/` signature files.
2. Resolves candidate upstream commits (`release.yml` workflow `head_sha` and the `v<version>` Git tag) and candidate Node.js runtimes matching `engines.node`, installing the exact `packageManager` declared in `package.json` inside an isolated directory.
3. Discovers `SYNC_*` build environment variable names from `.github/workflows/release.yml`, runs a sentinel build to structurally align and recover their values in memory from the AMO bundle, then performs a clean build from source and verifies that every file in `dist/` matches the unsigned AMO tree byte-for-byte.
4. Writes verified metadata to `releases/<version>.json`.

## CLI Usage

Requires Python 3.12+ and Node.js (or network access for automatic official Node.js provisioning).

```sh
# Print the latest version published on AMO
python3 -m repro latest

# Verify a concrete AMO release
python3 -m repro verify 2.50.0

# Verify and write releases/<version>.json
python3 -m repro verify 2.50.0 --write

# Verify a local .xpi file offline against upstream source
python3 -m repro verify 2.50.0 --xpi ./violentmonkey-2.50.0.xpi
```

## Nix Flake Metadata

`flake.nix` is a zero-input data flake that automatically exposes the highest verified release from `releases/*.json`:

- `lib.latestVersion`: latest verified version string
- `lib.violentmonkeyXpi`: `{ version, url, sha256 }`
- `lib.violentmonkeyBuildFirefoxXpiAddonArgs`: `{ pname, version, addonId, url, sha256 }`
- `lib.releases`: attribute set of all verified release records keyed by version

## Trust Scope

> **tophf**: Quick perusal of the code won't guarantee safety, it just gives you a false sense of security, which is just as bad as blind trust or maybe even worse.

Byte-for-byte reproduction proves that the AMO package corresponds to the recorded upstream commit and build inputs without release-stage tampering; upstream source code and third-party npm dependencies are not audited.
